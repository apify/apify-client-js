A [Server Actor](https://docs.apify.com/platform/actors/running/standby) (formerly Actor Standby) runs a web server. You call it over HTTP, and the platform keeps a run ready to answer, so each call skips the run startup.

:::note Formerly Actor Standby

Actor Standby is the former name of Server Actors, and it'll be deprecated. The platform documentation and the API still use it, for example in the Actor's `standbyUrl` and `actorStandby` fields. In the client, `ActorClient.standby()` is a deprecated alias of `ActorClient.server()` that will be removed in v4.

:::

To work with a Server Actor, get its server client with <ApiLink to="class/ActorClient#server">`ActorClient.server()`</ApiLink>. To send a request, use <ApiLink to="class/ActorServerClient#request">`ActorServerClient.request()`</ApiLink>. It takes the path on the Actor's server, and optionally the HTTP method, query parameters, headers, and a body:

The method resolves to the server's response, with the body parsed by its content type in `data`. To find out which endpoints an Actor serves, see its page in [Apify Store](https://apify.com/store), its README, or its OpenAPI specification. For details, see [Server URL and OpenAPI specification](#server-url-and-openapi-specification).

## How the request is sent

Note that:

- The client takes the server's URL from the Actor's `standbyUrl`. It fetches the Actor from the API on the first call and reuses the URL for later calls through the same `ActorClient`. If the Actor isn't a Server Actor, the server client throws an `ApifyClientError`.
- The path is always resolved against that URL, so a path can't send the request to another host.
- By default, the request body is sent uncompressed, since the Actor's server may not decode a compressed body. If the server decodes it, pass `compression`, for example `compression: 'gzip'`. The client then compresses large bodies the same way as for API calls.

## Server URL and OpenAPI specification

The Actor server client also gives you the server's URL and its OpenAPI specification:

- <ApiLink to="class/ActorServerClient#getUrl">`ActorServerClient.getUrl()`</ApiLink> returns the server's URL. It fetches and reuses the URL the same way as `request()`.
- <ApiLink to="class/ActorServerClient#getOpenApiSpec">`ActorServerClient.getOpenApiSpec()`</ApiLink> returns the server's OpenAPI specification as an object. It's the [web server schema](https://docs.apify.com/platform/actors/development/actor-definition/web-server-schema) from the Actor's definition, taken from the build that serves the server interface. That's the build set in the Actor's `actorStandby.build` field, or `latest` if none is set. If the Actor doesn't define a web server schema, the method returns `undefined`.

## Authentication

The request carries the client's API token in the `Authorization` header. The platform removes the token before it forwards the request, so the token doesn't reach the Actor's code.

If the Actor reads the `Authorization` header for its own authentication, pass that header in `headers`, and send your Apify token in the `X-Apify-Authorization` header instead. A header you pass in `headers` replaces the client's `Authorization` header for that request.

For details, see [How do I authenticate my requests](https://docs.apify.com/platform/actors/running/standby#how-do-i-authenticate-my-requests) in the platform documentation.

## Timeouts, retries, and errors

When no server run is ready, the first request waits for the platform to start one, which can take a few minutes. The method uses the `long` timeout tier by default for that reason. You can pass a different `timeoutSecs`, or a `signal` to abort the request, the same way as for API calls. For details, see [Timeouts](./10_timeouts.mdx).

An error status from the Actor's server throws an `ApifyApiError`, like an error from the API. Server errors and rate-limit responses are retried with the client's retry settings, so a request that the server failed to answer may reach it more than once. If your endpoint isn't safe to call twice, lower `maxRetries` on the client. For details, see [Retries](./04_retries.mdx) and [Error handling](./03_error_handling.mdx).
