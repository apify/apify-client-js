Certain resources, such as dataset items, key-value store records and logs, support streaming directly from the Apify API. You can then process large resources incrementally without downloading them entirely into memory, which suits large or continuously updated data.

Supported streaming methods:

- <ApiLink to="class/LogClient#stream">`LogClient.stream()`</ApiLink> - Stream a log in real time. Resolves to a web `ReadableStream`, or `undefined` when the log doesn't exist. A log client chained off a run or build, such as `client.run('run-id').log()`, throws a <ApiLink to="class/NotFoundError">`NotFoundError`</ApiLink> instead, since the run itself may be what is missing.
- <ApiLink to="class/DatasetClient#downloadItems">`DatasetClient.downloadItems()`</ApiLink> with the `stream: true` option - Stream dataset items serialized to a format such as CSV or XLSX. Resolves to a web `ReadableStream`.
- <ApiLink to="class/KeyValueStoreClient#getRecord">`KeyValueStoreClient.getRecord()`</ApiLink> with the `stream: true` option - Stream a key-value store record as raw data. Resolves to a record whose `value` is a web `ReadableStream`, or `undefined` when the record doesn't exist.
- <ApiLink to="class/RunClient#getStreamedLog">`RunClient.getStreamedLog()`</ApiLink> - Redirect the log of a run to a logger while the run is in progress. For details, see [Redirecting Actor run logs](./05_logging.mdx#redirecting-actor-run-logs).

A stream holds its connection open until you consume it to the end or cancel it. Iterating it with `for await` or passing it to `pipeline()` from `node:stream/promises` does either one for you, including when the processing throws.

## Upload a stream

A request body can be a stream too: <ApiLink to="class/KeyValueStoreClient#setRecord">`KeyValueStoreClient.setRecord()`</ApiLink> takes a web `ReadableStream` or a Node.js `Readable` as the record `value`, and sends it without holding it in memory. That includes the stream another call returned, so a record can be copied without being read first:

<CodeBlock className="language-ts">
    {UploadStreamExample}
</CodeBlock>

A stream can be sent only once, so the client neither retries such a request nor follows a redirect with it. To upload a file with retries, pass a `Blob` instead. For details, see [Retry a request body read from a file](./04_retries.mdx#retry-a-request-body-read-from-a-file).

Node.js, Bun and Deno send a stream of either type. A browser sends a web `ReadableStream` only if it supports streaming request bodies, and only over HTTP/2 or later. In a browser without that support, such as Firefox and Safari, the call throws a `TypeError`, so read the stream into a `Blob` first, for example with `await new Response(stream).blob()`.
