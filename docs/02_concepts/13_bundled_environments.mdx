:::warning Non-Node.js environments

This page applies only to non-Node.js environments (browsers, Cloudflare Workers, edge runtimes). If you're running on Node.js, you can skip it.

:::

## Browser bundle

The package ships a pre-built browser bundle at `dist/bundle.js`. A bundler that targets the browser picks it up through the `browser` condition of the package's `exports` field. If yours doesn't, import it directly:

```ts
import { ApifyClient } from 'apify-client/browser';
```

The bundle is self-contained and needs no polyfill configuration.

## Bundling the ES module build yourself

The client's own code runs on Web APIs. The parts that need Node.js built-ins, such as request body compression and streamed responses, live in a single module that the `#runtime` entry of the package's `imports` field selects at bundle time. The `node` condition gets the Node.js implementation, every other target gets the Web API one. A bundler targeting a browser, Cloudflare Workers, or another edge runtime therefore never sees `node:zlib`, `node:os`, or `node:stream`.

Reaching the ES module build takes a bundler that doesn't set the `browser` condition, which resolves `apify-client` to the pre-built bundle. esbuild's `neutral` platform sets no conditions, and webpack and Vite let you list them through `resolve.conditionNames` and `resolve.conditions`.

## Features that need Node.js

These features rely on Node.js APIs and aren't available in the browser bundle or in the Web API runtime:

- Log redirection with <ApiLink to="class/RunClient#getStreamedLog">`RunClient.getStreamedLog()`</ApiLink>.
- Request body compression.
- The `User-Agent` header, which browsers don't let a page set.

## Streams and raw bytes

Streamed responses work everywhere, but the stream is the one native to the runtime. <ApiLink to="class/LogClient#stream">`LogClient.stream()`</ApiLink>, the `stream` option of <ApiLink to="class/DatasetClient#downloadItems">`DatasetClient.downloadItems()`</ApiLink> and <ApiLink to="class/KeyValueStoreClient#getRecord">`KeyValueStoreClient.getRecord()`</ApiLink>, and `responseType: 'stream'` return a Node.js `Readable` under the `node` condition and a web [`ReadableStream`](https://developer.mozilla.org/docs/Web/API/ReadableStream) of `Uint8Array` chunks in the browser bundle and in the Web API runtime:

```ts
const record = await client.keyValueStore('my-store').getRecord('video.mp4', { stream: true });
const stream = record.value as unknown as ReadableStream<Uint8Array>;
const blob = await new Response(stream).blob();
```

Raw bytes, such as a binary record or the result of the `buffer` option, are a `Buffer` under the `node` condition and a plain `Uint8Array` everywhere else. A `Buffer` is a `Uint8Array` too, so code that sticks to the `Uint8Array` API runs in every runtime.

The published types describe the Node.js values, `Readable` and `Buffer`, so TypeScript code for another runtime has to cast a stream as in the example above.
